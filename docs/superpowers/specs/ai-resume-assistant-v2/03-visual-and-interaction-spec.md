# Web V2 视觉与交互规格

## 1. 设计方向

V2 采用 **Evidence Workbench / 证据工作台**，延续现有 Workbench + Cobalt 语言，不重新发明品牌。

它应像一张清楚的工作桌：

- 左侧说明“我在哪里”；
- 中间只处理当前任务；
- 右侧在需要时解释状态、来源和下一步；
- 界面安静，业务证据醒目；
- 不像营销模板、聊天机器人或 ATS 打分器。

视觉关键词：

- 可信；
- 克制；
- 清楚；
- 可核对；
- 对学生友好但不幼稚。

## 2. 信息层级

每个页面按固定优先级组织：

1. 当前任务；
2. 当前业务状态；
3. 主操作；
4. 证据或解释；
5. 次级导航。

页面不得用超大标题挤压主要工作区。业务页 `h1` 在 1440 px 下建议 36–48 px，在 390 px 下 30–36 px；营销页可更大，但不超过两行。

## 3. 导航

### 3.1 桌面 ≥1200 px

- 224 px 左侧导航；
- 顶部只保留当前路径、任务状态和账户菜单；
- 主入口：工作台、我的简历、经历事实、任务中心；
- 设置、协议、隐私和退出放在账户菜单底部；
- 当前项使用文字、左侧标记和对比度共同表示，不只改变颜色。

### 3.2 平板 768–1199 px

- 左栏收起为可访问抽屉；
- 顶部显示菜单按钮、当前页面和任务状态；
- 编辑器从三栏变为主编辑区 + 可收起上下文面板。

### 3.3 移动 <768 px

- 单列；
- 底部最多四个一级入口：工作台、简历、事实、任务；
- 账户设置从顶部账户按钮进入；
- 主要动作固定底部并避开安全区和键盘；
- 来源、建议和质量问题使用全屏 sheet。

### 3.4 命令面板

V2 P0 不展示伪“⌘ K”。P1 若实现：

- ⌘K/Ctrl+K 打开真实命令面板；
- 支持搜索简历和页面；
- 方向键、Enter、Escape 全部可用；
- 输入始终保持焦点；
- 未登录不出现用户资源；
- 搜索结果只来自已加载资源或受鉴权 API。

## 4. 页面结构

### 4.1 工作台

采用不对称工作台结构：

- 主栏约 2/3：唯一“下一步”及最近简历；
- 次栏约 1/3：任务和当日用量；
- 卡片不等高，不做三个完全一致的功能卡；
- 没有数据时用留白和一个真实动作，不放示例简历。

### 4.2 创建与导入确认

桌面：

- 220–240 px 进度栏；
- 中间最小 520 px 当前问题或字段确认；
- 320–360 px 事实/简历即时预览。

即时预览只展示已保存或明确标记“尚未保存”的内容，不能把当前输入即时排版后暗示已经写入服务端。

移动：

- 只显示当前问题；
- 进度用文本“第 n 个主题 · 预计还需 x–y 分钟”，避免虚假精确剩余题数；
- 预览从底部按钮打开全屏 sheet。

### 4.3 编辑器

桌面：

- 240 px 模块栏；
- `minmax(520px, 1fr)` 编辑区；
- 360 px 事实与质量栏；
- A4 预览独立打开，不与三栏同时挤压。

平板：

- 模块栏进入抽屉；
- 质量栏保持可折叠二栏。

移动：

- 模块列表 → 条目列表 → 字段编辑三级；
- 固定底部保存/下一步；
- 来源和冲突使用全屏 sheet。

### 4.4 匹配与建议

- 四类匹配不用四张完全相同的大卡；使用一条分类总览 + 可展开 requirement 列表；
- “真实缺口”不使用红色错误语气，采用紫色路标和解释；
- 单条建议以原文、建议、理由、事实来源、风险、决策的固定顺序展示；
- 事实来源在右栏或 sheet，不能埋在 tooltip。

## 5. 颜色

所有颜色继续引用 `packages/design-tokens` 的命名 Token，组件中不写临时 hex/rgb/OKLCH。

角色：

| Token | 角色 |
| --- | --- |
| `brand-600/700` | 主动作、选中态、链接、焦点 |
| `ink-950/700/500` | 主文本、次文本、辅助文本 |
| `surface-0/50` | 工作面和页面底色 |
| `line-200` | 分隔和控件边界 |
| `fact-600` | 已确认、有来源 |
| `pending-600` | 待确认、排队、未同步 |
| `risk-600` | 无来源、失败、删除和阻断 |
| `gap-600` | 真实能力缺口 |

规则：

- Cobalt 只用于主动作、焦点和小面积高亮，每个视口面积不超过约 5%；
- 不使用紫蓝渐变；
- 状态必须同时有文字和图标；
- 正文对比 ≥4.5:1，边界与焦点 ≥3:1，目标 4.5:1；
- placeholder 和 helper 文本同样 ≥4.5:1；
- 不以红/绿作为唯一差异。

## 6. 字体

界面沿用中文优先字体 Token：

```text
"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif
```

规则：

- 本轮不新增在线字体依赖，避免中文 fallback 和 CLS；
- 业务正文最小 16 px，helper 最小 14 px；
- 标题和正文至少相差 300 字重；
- 页面最多使用 5 个字号层级；
- 数字进度使用 tabular numbers；
- 标题保持正体，不使用斜体强调；
- 长文行宽 45–75 个字符。

## 7. 间距、边界和深度

- 4 px 基础网格；
- 使用 design-token 中 4、8、12、16、24、32、48、64 px 层级；
- 页面水平 padding 使用流式 Token，390 px 至少 16 px，1440 px 建议 48–64 px；
- 表单与普通面板圆角 8–12 px；
- 同一层级只使用一条 hairline 或一个 whisper shadow，不叠加阴影；
- 避免 card-in-card；字段组优先使用分隔线和留白；
- 主按钮 Web 最小高 44 px，所有触控目标至少 44×44 px。

## 8. 组件

### 8.1 NextAction

工作台唯一主行动：

- 任务名称；
- 为什么现在做；
- 预计真实步骤或等待范围；
- 一个主按钮；
- 失败时就地提供恢复。

### 8.2 AsyncTaskStatus

显示：

- queued/running/waiting_for_user/succeeded/failed/cancelled；
- 真实 stage 和 progress；
- 最近更新时间；
- 可取消或可恢复动作。

长任务超过 10 秒必须显示阶段，不用无限 spinner 掩盖。

### 8.3 FactStatus

- 已确认：对勾 + “已确认”；
- 待确认：问号 + “待确认”；
- 不采用：删除线图标 + “不采用”；
- 无来源：警告 + “无法导出”。

### 8.4 SourceDrawer

展示当前 claim、来源类型、必要原文摘录、确认时间和修改记录。禁止展示模型 thinking、完整 Prompt 或无关全文。

### 8.5 EmptyState

必须包含：

1. 什么为空；
2. 为什么有用；
3. 一个下一步动作。

禁止用示例业务卡填充空状态。

### 8.6 ErrorState

错误结构固定为：

1. 发生了什么；
2. 已知原因；
3. 用户下一步。

不使用“出错了”“Oops”“请稍后重试”作为唯一信息。

## 9. 八种交互状态

所有 Button、LinkButton、Field、Select、Tab、MenuItem、CardAction 和快捷键操作必须实现：

1. default；
2. hover；
3. focus-visible；
4. active；
5. disabled；
6. loading；
7. error；
8. success。

要求：

- focus ring 立即出现，不动画；
- loading 延迟 150 ms 显示且至少可见 300 ms，避免闪烁；
- disabled 仍保持可读，且通过 `disabled`/`aria-disabled` 表达；
- error 有文字、图标和边界变化；
- success 若结果已经可见则静默，不额外弹庆祝 toast；
- hover 只在 `(hover: hover) and (pointer: fine)` 下生效；
- 每个 hover 行为都有键盘或触控等价行为。

## 10. 动效

项目当前没有动效库，V2 保持 motion-cut：

- 按钮按压 100–150 ms；
- 菜单、tooltip 150–220 ms；
- drawer/dialog 220–300 ms；
- 只动画 transform 和 opacity；
- 页面不做逐区滚动 fade-up；
- 不做 parallax、光晕、弹跳或通用 hover scale；
- `prefers-reduced-motion` 下空间动画取消或降为 ≤150 ms 淡入淡出；
- 进度条可以 linear，但必须反映真实进度或明确不确定状态。

## 11. 响应式硬门禁

实现过程中检查 320、375、414、768 px；交付截图使用 390、1024、1440 px。

每个宽度：

- `documentElement.scrollWidth <= clientWidth`；
- h1、主要按钮、导航、面包屑和 footer 链接不被裁切；
- 可点击文字不换为两行；
- 输入框和固定操作区不被软键盘遮挡；
- `html` 和 `body` 使用 `overflow-x: clip`，不使用 `hidden` 掩盖错误；
- display 标题允许 `overflow-wrap:anywhere`；
- 200% 缩放仍可完成核心流程；
- 不使用 `100vw` 和固定 `100vh`。

## 12. 可访问性

- 每页唯一 h1，标题反映真实资源；
- 表单控件有 programmatic label；
- async 状态用 `aria-live="polite"`；
- 错误摘要可聚焦并链接到字段；
- dialog 使用原生 `<dialog>` 或等价 focus trap；
- Escape 关闭非阻断 overlay；
- 键盘可完成登录、创建、导入确认、编辑、建议和导出；
- A/E/I/Z 仅在非输入上下文生效；
- axe 严重/关键问题为 0；
- Lighthouse 核心页 Accessibility ≥90。

## 13. 文案

语气是严谨教练，不是营销机器人：

- 使用“已确认”“需要你确认”“没有证据”“不能直接导出”；
- 按钮写具体动词，如“保存回答”“确认 4 条事实”“开始匹配”；
- 不用“确定”“提交”“继续”代替可描述动作；
- 不使用“逆天改命”“一键上岸”“保证通过”；
- 不虚构用户数、成功率、Offer、合作品牌或评价；
- 时间、用量、任务数和简历数只显示真实 API 数据；
- 示例只可出现在 placeholder，并以“例如”开头。

## 14. Hallmark 交付门禁

页面实现后执行 Hallmark 58 项 slop test。任一适用项为 yes 就不能完成；尤其检查：

- 固定业务内容是否伪装成真实状态；
- 三张等宽同构卡片；
- 假命令面板或假交互；
- accent 面积过大；
- 交互文字换行；
- 水平溢出；
- 缺少八状态；
- 只用颜色表达；
- 通用 `transition-all`、hover scale 或散乱动画。
