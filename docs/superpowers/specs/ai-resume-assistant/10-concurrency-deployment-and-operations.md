# 并发、部署与运维

## 1. 容量基线

| 指标 | 公开 MVP 目标 |
| --- | --- |
| DAU | 1,000 |
| 峰值在线 | 100 |
| 普通 API 峰值 | 50 RPS |
| 同时 AI 任务 | 10–20 |
| 单用户同时 AI 任务 | 2 |
| 文件解析/导出并发 | 5–10 |
| 单文件 | ≤ 10 MB、≤ 10 页 |
| 日 AI 成本 | ≤ 100 元 |

设计允许通过增加 FastAPI、Worker 和 Pi 副本扩展到 1,000 峰值在线，不改变数据模型和公开 API。

## 2. 请求控制

### 2.1 外层

CDN/WAF/LB 负责：

- TLS；
- 静态资源；
- 每 IP 粗限流；
- 连接数保护；
- 请求体上限；
- 健康检查；
- 明显恶意流量拦截。

### 2.2 应用层

Redis 滑动窗口或令牌桶按以下维度限流：

- 用户；
- IP；
- route group；
- workflow；
- provider；
- 全局成本状态。

返回 `429` 时必须包含稳定错误码和 `Retry-After`，不得让客户端立即无限重试。

## 3. 队列

队列分离：

- `ai.interactive`：单段表达和下一题；
- `ai.batch`：初稿、匹配、批量校验；
- `file.parse`：导入；
- `file.export`：PDF；
- `privacy`：数据导出和删除。

优先级：

1. 用户当前等待的交互任务；
2. 导出；
3. 批量生成；
4. 后台维护。

防止低优先级饥饿：连续处理 10 个高优先级任务后至少处理 1 个普通任务。

## 4. Worker 并发

- AI Worker 默认并发 10；
- File Worker 默认并发 5；
- Pi 每实例默认并发 10；
- provider 维度设置独立 semaphore；
- 任务开始前重新检查用户、成本和 provider 限额；
- 不允许 Worker 自行突破全局阀门。

## 5. 过载和降级

| 条件 | 行为 |
| --- | --- |
| AI 排队 P95 > 30 秒 | 停止非必要自动重试，提示等待 |
| AI 队列深度 > 100 | 新批量任务返回 `TASK_QUEUE_BUSY` |
| provider 429 > 20/10 分钟 | 熔断该 provider 5 分钟 |
| 日成本 70% | 告警 |
| 日成本 90% | 禁止非必要 retry 和批量风格检查 |
| 日成本 100% | 停止新 AI 任务，编辑/预览/导出继续 |
| Redis 不可用 | 禁止新异步任务，同步读写继续 |
| Pi 不可用 | AI 功能降级为手动编辑 |
| 导出 Worker 不可用 | 版本可继续编辑，导出排队 |

## 6. 扩缩容

无需自建或维护 Kubernetes。生产默认部署在腾讯云中国大陆地域：

- Web、FastAPI、Pi 和 Worker 使用 CloudBase Run 容器托管；
- PostgreSQL 使用 TencentDB for PostgreSQL；
- Redis 使用腾讯云兼容 Redis 的托管实例；
- 文件使用 COS 私有桶；
- 静态资源使用腾讯云 CDN；
- WAF 与负载均衡位于公开 API 前；
- 所有业务服务、数据库和 Redis 位于同一 VPC。

云产品通过适配层接入，替换供应商不能改变公开 API、数据库模型或验收标准。

### 6.1 FastAPI

- 最少 2 个副本；
- CPU 持续 5 分钟 > 60% 或 P95 > 500 ms 时扩容；
- CPU < 25% 且请求稳定 30 分钟后缩容；
- 最大副本由预算配置。

### 6.2 Pi

- 初始 1 个副本；
- 活跃 run 达到实例并发 80% 持续 3 分钟时扩容；
- 扩容不提升 provider 全局并发上限；
- 会话状态由业务任务输入恢复，不能依赖单实例内存。

### 6.3 Worker

- AI 队列等待 > 30 秒扩容；
- File 队列长度 > 20 扩容；
- 缩容只终止空闲 Worker；
- 执行中的任务获得优雅关闭时间。

## 7. 数据库与 Redis

PostgreSQL：

- 托管实例；
- PgBouncer；
- API 每副本连接上限 10；
- Worker 每进程连接上限 5；
- 慢查询阈值 500 ms；
- 事务空闲超时；
- 自动备份和时间点恢复；
- 索引监控。

Redis：

- 托管实例；
- 使用密码和私网；
- 队列、限流、短锁和 Pub/Sub 分命名空间；
- 不存长期业务事实；
- 锁必须有过期时间；
- 关键任务状态同步写 PostgreSQL。

## 8. SLO

按 30 天滚动：

| 服务 | SLO |
| --- | --- |
| 登录后核心 API 可用性 | ≥ 99.5% |
| 非 AI API P95 | < 500 ms |
| 非 AI API P99 | < 1,000 ms |
| 异步任务受理 P95 | < 1,000 ms |
| AI 成功率（排除用户取消） | ≥ 95% |
| 导出成功率 | ≥ 99% |
| 保存成功率 | ≥ 99.9% |
| trace 完整率 | ≥ 99.5% |

错误预算耗尽后暂停功能发布，只允许可靠性和安全修复。

## 9. 监控面板

### 9.1 用户体验

- 登录成功率；
- 保存成功率和冲突率；
- 导入/导出成功率；
- 任务等待与执行时间；
- 两条流程完成率；
- Web Core Web Vitals；
- 小程序启动和页面耗时。

### 9.2 系统

- RPS、状态码、P50/P95/P99；
- FastAPI CPU、内存、连接；
- PostgreSQL 连接、锁、慢查询、磁盘；
- Redis 内存、连接、队列；
- Worker 活跃数、重试、失败；
- Pi run、turn、tool、token、cost；
- 对象存储错误和流量。

### 9.3 隐私

- 日志敏感信息扫描；
- 过期文件删除失败；
- 删除任务超时；
- 非授权访问；
- 密钥轮换时间。

## 10. 告警

| 严重级别 | 条件 | 响应 |
| --- | --- | --- |
| Sev1 | 数据泄露、跨用户访问、无来源严重事实导出 | 立即停止相关功能，15 分钟内确认 |
| Sev2 | 保存成功率 < 99%、核心 API 5xx > 5%/5 分钟 | 30 分钟内处理 |
| Sev2 | PostgreSQL 不可写或任务丢失 | 30 分钟内处理 |
| Sev3 | AI 成功率 < 95%/10 分钟 | 4 小时内处理或降级 |
| Sev3 | 队列等待 P95 > 30 秒/10 分钟 | 4 小时内扩容或限流 |
| Sev4 | 单一非核心页面问题 | 下一维护窗口 |

## 11. 备份与恢复

- PostgreSQL 每日全量加持续日志；
- RPO ≤ 15 分钟；
- RTO ≤ 4 小时；
- 对象存储启用版本/生命周期策略；
- Redis 不作为恢复业务数据的来源；
- 每季度执行一次隔离环境恢复；
- 恢复后抽查 20 个版本哈希、20 个事实来源和 10 个任务状态；
- 证据包含开始时间、完成时间、数据校验和差异。

## 12. 发布

流水线：

1. lint、type check；
2. 单元、集成、契约；
3. AI 固定评测；
4. Web、小程序构建；
5. 镜像安全与依赖扫描；
6. 数据库迁移预检；
7. 测试环境 E2E；
8. 性能冒烟；
9. 生成验收证据索引；
10. 人工批准生产发布。

生产发布：

- FastAPI、Pi、Worker 使用不可变镜像和 commit SHA；
- FastAPI/Pi 先 10% 流量 30 分钟；
- 关键指标正常后到 100%；
- 小程序按平台审核流程发布；
- 每次保留上一稳定镜像和模板；
- 数据库变更必须向后兼容至少一个应用版本。

## 13. 回退

触发：

- 5xx > 2% 持续 5 分钟；
- 保存或版本错误；
- trace 丢失；
- AI 无来源事实回归；
- 导出内容与预览不一致；
- 安全事件。

回退顺序：

1. 关闭功能开关；
2. 回退模型/Prompt；
3. 回退应用镜像；
4. 禁止直接回滚破坏性数据库迁移；
5. 验证保存、读取、导出和任务恢复。

## 14. 负载与故障演练

发布前必须执行：

- 100 虚拟用户、50 RPS、15 分钟非 AI API 测试；
- 100 个模拟 AI 任务、并发 20；
- 30 个文件任务、并发 10；
- 重启一个 FastAPI 副本；
- AI Worker 执行中退出；
- Pi 返回 429、500、超时和非法 Schema；
- Redis 中断 60 秒；
- 对象存储上传/下载失败；
- PostgreSQL 只读故障；
- 全局成本达到 70%、90%、100%。

具体通过阈值和证据见[验收与证据标准](./11-acceptance-and-evidence.md)。
