# Web 功能规格

## 1. Web 目标

Web 是完整生产端，不是小程序的管理后台。它承担桌面深度编辑，同时在手机浏览器中保留完整功能。

支持范围：

- Chrome、Edge、Safari 当前稳定版及前一个主版本；
- 桌面宽度 1280–1920 px；
- 平板宽度 768–1279 px；
- 移动 Web 宽度 360–767 px。

## 2. 路由

| 路由 | 页面 |
| --- | --- |
| `/` | 营销首页与登录入口 |
| `/login` | 邮箱验证码登录 |
| `/home` | 用户首页 |
| `/create` | 从零创建向导 |
| `/imports/:id/confirm` | 导入确认 |
| `/resumes` | 我的简历 |
| `/resumes/:id/edit` | 简历编辑器 |
| `/resumes/:id/versions` | 历史版本 |
| `/jobs/new` | JD 输入 |
| `/jobs/:id/match` | 匹配报告 |
| `/suggestions/:analysisId` | 逐条优化 |
| `/facts` | 经历事实库 |
| `/tasks` | 任务中心 |
| `/exports/:id` | 导出结果 |
| `/settings` | 账号、隐私和数据 |

未登录访问用户数据路由时跳转登录，并保留安全的站内返回地址。外部传入的返回地址不得直接用于跳转。

## 3. 首页

### 3.1 未登录

- 首屏一句价值主张；
- “我还没有简历”“我已经有简历”两个等权入口；
- 事实保护说明；
- 不展示虚构用户数、Offer 数或面试提升率。

### 3.2 已登录

- 继续最近任务；
- 新建基础简历；
- 导入并优化；
- 最近三份简历；
- 进行中和失败任务；
- 当日 AI 用量。

## 4. 从零创建向导

桌面使用“左侧步骤 + 中间问题 + 右侧即时预览”；平板和移动 Web 使用单列分步布局。

要求：

- 页面始终显示当前步骤和预计剩余问题数；
- 每题均可跳过；
- 开放题输入上限 1,000 个中文字符；
- 用户确认一段经历后，右侧立即显示生成条目；
- 浏览器刷新后恢复到最后成功保存的问题；
- 后退不删除已确认事实。

## 5. 导入确认

支持拖拽上传和文件选择。上传前显示格式、大小和页数规则。

确认页面按模块展示解析结果：

- 基本信息；
- 教育；
- 实习；
- 项目；
- 校园与活动；
- 技能；
- 荣誉。

每个字段标记 `confirmed`、`uncertain` 或 `missing`。不使用不可解释的百分比置信度。用户可以编辑、删除或改变模块类型。

## 6. 简历编辑器

### 6.1 桌面布局

- 左栏 240 px：模块导航、完整性状态、历史版本；
- 中栏最小 520 px：结构化内容编辑；
- 右栏 360 px：AI 建议、事实来源、质量检查；
- 纸张预览以独立模式打开，不与文本输入争夺宽度。

### 6.2 编辑能力

- 增删模块；
- 模块排序；
- 条目排序；
- 修改标题、角色、时间、地点和要点；
- 要点新增、删除、拆分和合并；
- 撤销最近 20 次本地编辑；
- 自动保存和保存状态；
- 字数、页数和分页提示；
- 一键定位质量问题。

编辑器是结构化编辑器，不允许任意 HTML、任意字号、绝对定位或自由画布。

### 6.3 并发编辑

每次保存携带 `base_version`。若服务端版本已经变化：

- 当前页面停止自动覆盖；
- 展示冲突模块；
- 用户选择“使用本地内容”“使用云端内容”或逐字段合并；
- 合并后创建一个新版本，保留两个父版本的审计记录。

## 7. JD 匹配与逐条建议

匹配报告顶部不展示单一 ATS 总分。展示四个分类数量和证据覆盖情况。

每条要求可以展开查看：

- JD 原文；
- 重要级别；
- 关联事实；
- 当前简历位置；
- 建议的下一步。

逐条建议视图支持键盘操作：

- `A` 接受；
- `E` 编辑；
- `I` 忽略；
- `Z` 撤销；
- 快捷键只在焦点不位于文本输入框时生效。

## 8. 预览与导出

- A4 纸张比例；
- 100%、适宽和整页缩放；
- 明确显示分页线；
- 模板切换不得修改内容；
- 导出前重新运行事实和完整性检查；
- 生成完成后提供下载，文件名为“姓名-目标岗位-日期.pdf”；
- 文件名中的非法字符被替换为连字符。

## 9. Web 可访问性

- 所有表单控件有关联标签；
- 键盘可完成登录、创建、编辑、建议处理和导出；
- 可见焦点样式；
- 正文和背景对比度至少 4.5:1；
- 错误不能只依靠颜色表达；
- 动画遵循 `prefers-reduced-motion`；
- 页面标题和主标题唯一且可识别。

## 10. Web 性能目标

- 营销首页移动端 Lighthouse Performance ≥ 85；
- 登录后核心页面 Lighthouse Accessibility ≥ 90；
- LCP P75 ≤ 2.5 秒；
- CLS P75 ≤ 0.1；
- 首次加载的编辑器路由 JavaScript gzip ≤ 350 KB，不含按需加载的 PDF 预览库；
- 非 AI 页面切换在已有网络连接下 P75 ≤ 1 秒显示可交互内容。

## 11. Web 测试证据

必须提交：

- Playwright 两条端到端流程视频或 trace；
- 桌面 1440×900、平板 1024×768、移动 390×844 截图；
- Chrome、Edge、Safari 兼容记录；
- Lighthouse JSON；
- 自动保存、冲突合并和刷新恢复的网络日志；
- 导出前后文本哈希对比结果。
