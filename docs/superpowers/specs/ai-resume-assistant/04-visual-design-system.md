# 视觉设计系统

## 1. 视觉定位

关键词：

- 可信；
- 克制；
- 清楚；
- 有指导感；
- 对学生友好但不幼稚。

产品应像一位严谨、耐心的求职表达教练，而不是聊天机器人、模板商城或制造焦虑的 ATS 评分器。

## 2. 品牌表达

### 2.1 语气

- 使用“事实”“依据”“待确认”“真实缺口”等直接词汇；
- 不使用“逆天改命”“一键上岸”“保证通过”等承诺；
- 不把用户称为“小白”；
- 错误信息先说明结果，再给恢复操作；
- AI 建议统一使用建议语气，不使用命令语气。

### 2.2 页面层级

每个页面只能有一个主要任务和一个主要按钮。危险操作不与主按钮并列使用同一颜色。

## 3. 颜色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `brand-600` | `#4F46E5` | 主按钮、选中态、链接 |
| `brand-700` | `#4338CA` | 主按钮悬停 |
| `ink-950` | `#111827` | 主文本 |
| `ink-700` | `#374151` | 次级文本 |
| `ink-500` | `#6B7280` | 辅助文本 |
| `surface-0` | `#FFFFFF` | 页面与卡片 |
| `surface-50` | `#F8FAFC` | 页面背景 |
| `line-200` | `#E5E7EB` | 边框和分隔 |
| `fact-600` | `#059669` | 已确认事实 |
| `pending-600` | `#D97706` | 待确认 |
| `risk-600` | `#DC2626` | 无来源、删除和阻断 |
| `gap-600` | `#7C3AED` | 真实能力缺口 |

规则：

- 状态同时使用颜色、图标和文字；
- 正文对比度至少 4.5:1；
- 大号文本和非正文图形至少 3:1；
- 简历导出模板默认黑白，不依赖界面品牌色。

## 4. 字体

界面字体栈：

```text
"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif
```

简历导出：

- 首选嵌入可商用的 Noto Sans CJK SC；
- 正文 9.5–10.5 pt；
- 标题 14–18 pt；
- 行距 1.35–1.5；
- 字体嵌入失败时导出任务失败，不静默替换成缺字字体。

## 5. 间距与圆角

- 基础网格：4 px；
- 常用间距：4、8、12、16、24、32、48 px；
- 表单和卡片圆角：8–12 px；
- 主按钮最小高度：Web 40 px，小程序 44 px；
- 可点击目标最小尺寸：44×44 px；
- 页面内容最大宽度：1440 px；
- 长文本阅读宽度：640–760 px。

## 6. 核心组件

### 6.1 事实状态标签

- 已确认：绿色对勾 + “已确认”；
- 待确认：琥珀色问号 + “待确认”；
- 已拒绝：灰色删除线 + “不采用”；
- 无来源风险：红色警告 + “无法导出”。

### 6.2 来源抽屉

展示：

- 当前文本片段；
- 来源类型；
- 用户原回答的必要摘录；
- 确认时间；
- 修改记录。

不得展示模型思维过程或与该片段无关的完整上下文。

### 6.3 四类匹配卡

| 类型 | 图标 | 主文案 |
| --- | --- | --- |
| 已证明 | 对勾 | 简历已有明确证据 |
| 表达不足 | 文本编辑 | 做过，但当前表达不够清楚 |
| 待确认 | 问号 | 有线索，需要你的回答 |
| 真实缺口 | 路标 | 当前没有证据，不能靠改写补齐 |

### 6.4 AI 建议卡

固定结构：

1. 对应 JD；
2. 当前原文；
3. 建议文本；
4. 修改理由；
5. 事实来源；
6. 风险；
7. 接受、编辑、忽略。

## 7. Web 布局

### 7.1 ≥ 1280 px

- 侧边主导航；
- 编辑器三栏；
- 来源和建议固定右栏；
- 纸张预览使用独立覆盖层或分屏。

### 7.2 768–1279 px

- 主导航收起；
- 编辑区与建议区二栏；
- 模块导航进入抽屉。

### 7.3 360–767 px

- 单列；
- 底部固定主要动作；
- 建议和来源使用全屏抽屉；
- 保留全部业务能力。

## 8. 小程序布局

- 底部四项主导航；
- 每页一个主要任务；
- 编辑器按模块和条目分层；
- 主要操作固定底部；
- 键盘弹起时操作区上移；
- 弹窗只用于短确认，长内容使用新页面或底部抽屉；
- 系统导航返回前检测未保存变更。

## 9. 动效

- 页面和抽屉 150–220 ms；
- 保存状态淡入淡出 150 ms；
- 不使用循环加载动画掩盖长任务，长任务必须显示真实阶段；
- 遵循减少动态效果设置；
- 事实风险不得使用抖动、闪烁等制造焦虑的动效。

## 10. 模板

本版本提供两个单栏模板：

1. **清晰标准**：左对齐、黑白、紧凑、适合技术和通用岗位。
2. **现代留白**：更明显的章节间距和细分隔线，适合产品、设计和运营。

共同约束：

- 不使用头像、评分条、技能进度条、图表或双栏；
- 文本顺序与结构化数据一致；
- 机器复制后阅读顺序正确；
- 切换模板不修改内容；
- 一页优先，但不得通过小于 9.5 pt 字体强行压缩。

## 11. 视觉验收

- Web 三个断点和小程序 320/375/430 px 无水平滚动；
- 200% 浏览器缩放仍可完成核心流程；
- 颜色对比自动扫描零个严重问题；
- 状态去掉颜色后仍能通过文字和图标区分；
- 10 名测试用户中至少 9 名能正确解释“待确认”和“真实缺口”的区别；
- 导出模板经文本复制验证，章节顺序与数据模型一致。
