# 验收与证据标准

## 1. 判定规则

每项只允许：

- `PASS`：达到阈值且证据完整；
- `FAIL`：未达到阈值；
- `BLOCKED`：环境或外部依赖阻断，等同于版本不可发布。

禁止使用“基本通过”“大体正常”“肉眼看起来没问题”。

公开发布必须同时满足：

1. 本文所有 P0 条目为 `PASS`；
2. 未关闭 Sev1、Sev2 缺陷为 0；
3. 测试证据对应同一 `commit_sha` 和候选版本；
4. `pnpm lint`、`pnpm test`、`pnpm build` 返回 0；
5. Web 和小程序审核用构建与验收构建哈希一致；
6. 数据库迁移、模型/Prompt、模板和配置版本全部记录。

## 2. 证据目录

```text
artifacts/acceptance/<release-id>/
├── manifest.json
├── commands/
├── contracts/
├── unit-integration/
├── e2e-web/
├── e2e-miniprogram/
├── ai-evaluation/
├── file-export/
├── performance/
├── security-privacy/
├── observability/
├── visual-accessibility/
├── operations/
└── user-validation/
```

`manifest.json` 必须包含：

- `release_id`
- `commit_sha`
- `created_at`
- Web、API、Pi、Worker 镜像摘要；
- 小程序构建版本；
- 数据库 schema version；
- Prompt、workflow、模型路由和模板版本；
- 测试环境；
- 每项验收 ID、状态、证据相对路径、证据 SHA-256；
- 执行者和复核者。

证据规则：

- 命令证据包含完整命令、开始/结束时间、退出码和原始输出；
- UI 截图不能单独证明数据写入，必须配 API/数据库断言；
- 性能证据使用原始结果文件，不只提交摘要截图；
- AI 评测保留匿名输入、输出、原子声明标注和统计脚本结果；
- 证据不得包含真实用户简历、邮箱、手机号或模型密钥。

## 7. AI、事实与 JD

### 7.1 标注方法

固定评测集至少 100 条生成样本，覆盖：

- 模糊角色；
- 团队成果和个人贡献混淆；
- 用户明确表示“没有”；
- 缺失数字；
- 诱导模型补数字；
- 工具和技能近义词；
- 冲突来源；
- 中英文缩写；
- JD 缺失关键词；
- 真实能力缺口。

两名评审独立把生成文本拆成原子声明并标记 `supported`、`needs_confirmation`、`unsupported`。Cohen's kappa ≥0.75；分歧由第三次复核裁决。

“严重无来源事实”包括新增或改变角色、单位、职位、技能、工具、数字、奖项和业务结果。
