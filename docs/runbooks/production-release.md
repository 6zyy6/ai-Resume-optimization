# 生产发布

发布输入必须包含 Git `COMMIT_SHA`、镜像摘要、迁移版本、OpenAPI hash、小程序构建版本和证据清单。

1. 在临时数据库执行备份恢复演练；确认迁移只包含向后兼容的新增。
2. 构建并扫描 `${COMMIT_SHA}` 镜像，禁止 `latest`。
3. 先迁移，再部署 10% 金丝雀，观察 30 分钟。门禁：5xx <1%、p95 不退化超过 20%、队列最老任务 <120 秒、Pi 失败率 <5%、成本状态低于 90%。
4. 逐步提升流量；API 始终至少两个副本，AI Worker 和文件 Worker 独立扩容。
5. 对照 `/version` 和 trace 属性确认所有服务运行同一提交。

任何 P0 `FAIL/BLOCKED`、迁移不可回退、证据 hash 不匹配时停止发布。
